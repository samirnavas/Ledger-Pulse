# LedgerPulse final redesign audit and release verification

**Release decision — Blocked.** The isolated PostgreSQL baseline and the command sync driver have test evidence. The Flutter app still uses the legacy persistence and synchronization contracts. Full-stack Supabase and device release gates remain open. This review did not apply hosted changes, deploy, or publish anything.

**Scope** — The current working tree, including the prior redesign changes already present at the start of this review. **Verified and passed** applies only to the named implementation and environment. **Failed** means a check ran and did not meet its expectation. **Not tested** means the behavior has no executed evidence here. **Blocked** identifies a missing prerequisite or an incomplete implementation.

## 1. Database structure

The separate fresh-start workdir defines 19 public application tables. Managed `auth.users` remains the login identity. `public.users` stores personal information and preferences, with its UUID keyed to Auth. `public.workspaces` owns common identity, owner, type, currency, lifecycle and sequence metadata. Each workspace commits with exactly one matching `expense_profiles` or `ledger_profiles` row. Ledger business details are keyed directly by workspace. `workspace_memberships` is a distinct delegation roster. Owner access is derived from the workspace and delegated roles grant no launch access. [Fresh-start schema](../../supabase/fresh-start/supabase/migrations/20261121203449_ledgerpulse_schema.sql#L25) · [Subtype enforcement](../../supabase/fresh-start/supabase/migrations/20261121203450_ledgerpulse_commands.sql#L393)

- **Expense** — `expense_wallets`, `expense_categories`, `expense_recurring_rules`, `expense_transactions`, and `expense_budgets`. Transfers use one transaction row with both wallet references. Recurring templates and occurrence identity are relational. [Expense DDL](../../supabase/fresh-start/supabase/migrations/20261121203449_ledgerpulse_schema.sql#L106)
- **Ledger** — `ledger_parties`, `ledger_accounts`, `ledger_inventory_items`, `ledger_vouchers`, `ledger_voucher_lines`, `ledger_journals`, `ledger_journal_lines`, `ledger_stock_movements`, and `ledger_audit_events`. Vouchers preserve document data. Posted journal lines are the accounting facts, and `ledger_party_activity` derives the party view. [Ledger DDL](../../supabase/fresh-start/supabase/migrations/20261121203449_ledgerpulse_schema.sql#L220) · [Party projection](../../supabase/fresh-start/supabase/migrations/20261121203450_ledgerpulse_commands.sql#L975)
- **Infrastructure** — `private.workspace_commits` stores accepted operation receipts and ordered batches. Supabase Storage policies scope private objects by account or workspace. [Commit table](../../supabase/fresh-start/supabase/migrations/20261121203449_ledgerpulse_schema.sql#L433) · [Storage policies](../../supabase/fresh-start/supabase/migrations/20261121203450_ledgerpulse_commands.sql#L464)

**Verified and passed in PostgreSQL 17.5 fixtures.** The catalog contained 52 validated application FKs, 30 of them composite. The database contract rejected the tested missing or wrong subtype and cross-workspace references, and exercised independent workspace creation by one owner. The scoped DDL covers transaction wallets and categories, recurring templates, Ledger documents, account parents, journal dimensions and stock relationships. Audit subjects and Storage object strings are deliberate exceptions to ordinary relational FKs and rely on controlled write paths and policy checks. These results establish the checked-in baseline. The effective catalog of a deployed service is **not tested**. [Database contract](../../supabase/fresh-start/supabase/tests/ledgerpulse_database.test.sql) · [Fixture harness](../../supabase/fresh-start/verify-postgres.cjs)

## 3. Redundant schema and code cleanup

**Excluded from the new baseline** — `user_profiles`, `profiles`, `companies`, `shared_memberships`, `shared_devices`, legacy `exp_*` names, legacy `budgets` and `recurring_rules`, and the old unprefixed Ledger tables. `ledger_entries` has no parallel write table in the new baseline. `companies_json`, `active_company_id`, duplicated company/profile identity and row-upsert RPCs are outside the new schema. No hosted table or installed table was physically removed during this review. [Execution report and full exclusions](database_migration_execution_report.md#obsolete-structures-excluded-from-the-baseline)

**Retained in the checkout** — The reference sweep included app sources, generated Drift code, tests, SQL history, operational scripts and architecture documents. Auth, workspace bootstrap, company-scoped reporting, legacy sync payloads, SQLite FKs and historical migrations still depend on legacy representations. Reusing old names or finding a declaration only in generated code is insufficient evidence for a deletion that affects installed data.

- `SharedDevices`, `UserPreferences`, and `ExpenseAttachments` have no active application CRUD found outside schema code. They remain migration dependencies and removal candidates after data inspection and a supported upgrade path. Budget and recurring legacy tables continue to support upgrades, reconciliation and legacy sync. [Drift schema and upgrades](../../lib/data/local/database.dart#L386)
- The API and local-asset Ledger adapters and the alternate typed Expense repository have dedicated tests. The normalized sync driver has contract tests and a defined future integration point. These remain useful for verification. No independent unused DAO with a proven safe deletion was identified. [API adapter tests](../../test/api_ledger_repository_test.dart) · [Asset adapter tests](../../test/local_ledger_repository_test.dart) · [Typed Expense tests](../../test/expense/expense_domain_test.dart)
- Removed one duplicate active-workspace lookup from the company provider. The earlier identical check already returns a match and no input changes before the repeated lookup. Existing fallback order and creation gating remain in place. No tests were modified. [Provider cleanup](../../lib/presentation/providers/company_providers.dart#L110)

## 4. Drift and synchronization

Drift `schemaVersion` is **15** with 25 generated tables. V15 adds `expense_categories.archived_at` and backfills it from matching legacy Expense category accounts in the same scope. The v13 payment metadata and v14 Expense budget metadata remain. User-scoped files, isolated debug namespaces and preserving the oldest unscoped file are data-protection measures. The schema still includes legacy identity and financial models. Repository-level scoped checks and legacy sync guards do not establish database-level composite scope FKs across all SQLite tables. **Blocked** until target local models, safe data conversion, composite relationships and app projections replace the legacy stack. [Local schema](../../lib/data/local/database.dart#L647) · [Generated Drift bindings](../../lib/data/local/database.g.dart) · [Native file isolation](../../lib/data/local/connection/native.dart)

The normalized driver persists an optimistic change and stable command ID in one local transaction. Incoming changes and their checkpoint commit together. On conflict a stale command stops the workspace queue, with explicit reconciliation and a fresh intent required to retry. Deleted workspaces invalidate the confirmed projection and require a new snapshot after restoration. The installed client still uses the older engine, where table-scoped pulls and session checks are in place but separate row writes can expose a partially reconciled posting between sync operations. [Sync design, current limits and Task 5 evidence](workspace_sync_verification.md)

## 5. RLS verification

**Verified and passed in isolated PostgreSQL.** All 19 public application tables have RLS. No `anon` role had table access or execution of the six public LedgerPulse command functions. The `authenticated` role had SELECT grants on the public tables, zero raw write grants, and execute permission on the six controlled functions. The private feed had RLS and no direct authenticated SELECT grant. The party projection is a security-invoker view. Contract assertions covered unrelated accounts, active roster membership granting no launch access, protected writes, Storage path isolation, and action scope. [Policy setup](../../supabase/fresh-start/supabase/migrations/20261121203450_ledgerpulse_commands.sql#L532) · [RPC grants](../../supabase/fresh-start/supabase/migrations/20261121203450_ledgerpulse_commands.sql#L989)

**Blocked for full Supabase.** `supabase test db --local` could not reach PostgreSQL at `127.0.0.1:55432`, and the Windows Docker engine pipe was unavailable. Managed Auth and Storage, PostgREST with real JWTs, platform grants, advisors and installed-client compatibility were **not tested** on a verified isolated Supabase stack. Legacy database authorization risks identified in Task 1 remain open until effective deployed policies and grants are checked. No production database was selected as a test target. [Initial RLS audit](database_audit.md#5-authorization-and-rls)

## 7. Release checks and risks

Release verification was executed on Windows with the installed Flutter SDK. The release configuration retains **Coming Soon** on both workspace creation entry points. The release root gate prevents opening the Ledger home and leaves the Expense path available. [Onboarding gate](../../lib/presentation/auth/profile_onboarding_screen.dart#L246) · [Company creation gate](../../lib/presentation/home/create_company_flow.dart#L391) · [Release route guard](../../lib/presentation/auth/app_root_gate.dart#L55)

| Gate | Result |
| --- | --- |
| Full Flutter static analysis | **Verified and passed.** `flutter analyze --no-pub` found no issues. Targeted analysis of the changed provider also passed. |
| Focused financial, workspace, migration, sync and onboarding regression run | **Verified and passed.** 162 tests passed after the provider cleanup. It covered the local refund and reversal case, source and destination wallet movements, budget rollover, recurring transactions, duplicate saves, local isolation, onboarding and the simulated command feed. |
| In-memory PostgreSQL contract and catalog | **Verified and passed.** Both fresh-start migrations, command contract and grant diagnostics ran on PostgreSQL 17.5. |
| Full Supabase local suite | **Blocked.** No running local Docker-backed Supabase database. |
| LedgerPulse installed-device integration | **Not tested.** No app-level integration runner is present and the normalized client is unwired. No release APK was installed for this audit. |
| Android release build | **Verified and passed.** `flutter build apk --release --no-pub` built a fresh 79.1 MB APK after 708.7 seconds of Gradle work. [Local APK](../../build/app/outputs/flutter-apk/app-release.apk) |
| Android signing and distribution | **Failed.** Android SDK `apksigner verify` returned `DOES NOT VERIFY` and `Missing META-INF/MANIFEST.MF`. The checkout has no `android/key.properties` production signing configuration, and its Gradle script permits unsigned release builds. Distribution is blocked. [Signing configuration](../../android/app/build.gradle.kts#L47) |
| iOS build | **Blocked.** Windows has no supported iOS build toolchain. iOS widget variants in the Flutter suite are separate from an iOS native build. |
| Legacy SQL compatibility test | **Blocked.** The legacy DuckDB script requires Python with DuckDB. No Python executable was available on PATH. The fresh-start PostgreSQL contract ran separately. |

The focused run used `expense_repository_test.dart`, `expense_posting_test.dart`, `budgets_and_recurring_test.dart`, `drift_ledger_repository_test.dart`, `ledger_release_reports_test.dart`, `double_entry_accounting_test.dart`, `architecture/database_architecture_test.dart`, `database_migration_test.dart`, `profile/workspace_lifecycle_and_immutability_test.dart`, `auth/session_initialization_test.dart`, `sync/workspace_command_sync_test.dart`, and `ui/account_profile_ui_test.dart` under `test/`.
