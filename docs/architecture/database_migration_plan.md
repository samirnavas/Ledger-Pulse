# LedgerPulse database migration plan

**Status** — Proposed sequence for review. No SQL, schema changes or application implementation are part of this deliverable. See the [target specification](database_target.md), [ERD](database_erd.md) and [source audit](database_audit.md).

## 1. Preconditions and identity rules

1. Obtain an authorized catalog export of schemas, RLS/grants/functions, constraints, migration state and Storage policies. Reconcile baseline DDL gaps and out-of-band workspace tables before authoring migrations. Resolve the audit's critical privileged mutation finding as an independent prerequisite to relying on the cloud boundary.
2. Inventory actual states and usages by version and workspace. Record pre-migration counts, monetary totals, volumes, role assignments, legacy ID collisions, orphaned and misplaced data, storage references, and offline outbox and database versions. Confirm verified scope and ownership from authoritative evidence.
3. Preserve valid Auth UUIDs. For non-UUID business IDs, create a migration-only manifest keyed by source system, domain/table namespace, legacy workspace and legacy record ID. Allocate one immutable target UUID per proven entity. Keep distinct keys distinct within a scope, and persist mapping decisions across retries. Map local-only records using the same known cross-device identity rules or preserve them as local recovery candidates. Resolve UUID collisions and nonmatching profile/company pairs explicitly. A placeholder ID or one-row legacy DB never proves ownership.
4. Obtain finance/product decisions for unresolved semantics in the target specification. Quarantine unverified scope, currency, relationship, date and accounting mappings, keeping evidence with restricted access. A report of quarantined rows is part of migration acceptance. No silently skipped records or automatic owner inference.

## 2. Table and field mapping

| Legacy cloud / local | Target and conversion |
| --- | --- |
| `auth.users` | Keep. Verify subscriber identities and SDK sign-in before and after cutover. |
| `user_profiles` | Split verified UID and personal display/preferences to `users`. Verified contacts remain in Auth. Move owned business data to an identified Ledger profile only where mapping is verified. Treat prior role, `companies_json`, and `active_company_id` as compatibility/recovery input. Recover device selection separately. |
| `profiles` and `companies` | Merge to one `workspaces` row plus exactly one typed profile. Use validated owner and type, resolve divergences with source-specific provenance, preserve timestamps/lifecycle, and map known business settings into columns. Treat distinct IDs as aliases only with proof of identity. Preserve dormant or deleted markers. |
| `shared_memberships` | Deduplicate validated workspace/user pairs. Interpret current owner rows through `workspaces.owner_user_id`. Preserve genuine delegated roles as dormant roster history after mapping ambiguous legacy roles for review. Launch RLS grants those rows zero permissions. |
| `shared_devices`, local `user_preferences` and preference keys | Use Auth sessions for authentication and device-local selection under the current UID. Retire unused device and preference persistence after confirming dependencies and honoring retention. Move approved account-level preferences into personal rows. |
| `exp_wallets` / `expense_wallets` | Normalize wallet fields and confirmed opening amount. Rebuild current balance. Compare to old actual balance and quarantine missing/reconstructed openings where mismatched. Map archived state and visual settings. |
| `exp_categories` / `expense_categories` and category overlay in `accounts` | Consolidate the Expense category with its proven hierarchy, kind, system key and archive metadata. Preserve duplicate or disputed candidates for review and validate tree integrity. |
| `exp_transactions` / `expense_transactions` and legacy Expense vouchers | Keep verified typed transactions and link proven legacy source IDs to the same target. Compare amounts, time, currency, wallets, category, status and receipt before deduplication. Reject guessed default destinations or categories. Transfer remains one transaction. |
| `exp_budgets` / `expense_budgets`, legacy `budgets` | Convert Expense budgets with NULL overall scope, confirmed period start, activation and rollover. Use v14 local fields/backfill as evidence. Preserve historically distinct rules and resolve duplicate live period/category keys before activation. Retain legacy Ledger-specific data in restricted evidence until product disposition is confirmed. |
| `exp_recurring_rules` / `expense_recurring_rules`, legacy `recurring_rules` | Decode templates into typed wallet/category, amount and schedule fields. Recover links and date keys for generated transactions only from validated provenance. Preserve active state and next due date. Park state if its time zone or date semantics cannot be established. Legacy Ledger-specific schedules follow the same disposition gate as Ledger budgets. |
| Local `expense_attachments`, receipt URLs and Storage | Convert agreed single receipts to verified private keys. Inventory extra attachment rows and inaccessible or unscoped URLs. Preserve unconverted files and evidence until policy and cardinality decisions are approved. |
| `parties`, Ledger share of `accounts` | Map masters to `ledger_parties` and `ledger_accounts`. Preserve tax and contact facts, archive status, codes/system keys and hierarchy. Recalculate balances from proven postings and opening entries. |
| Ledger share of `vouchers` | Normalize documents into `ledger_vouchers` and typed `ledger_voucher_lines`. Preserve numbering and status, source conversion links, approved sell/buy/tax/payment semantics and historical item/party snapshots. Validate calculated totals against the persisted documents and explicit rounding policy. |
| Ledger share of `journals`, `journal_lines`, `ledger_entries` | Import proven postings and their lines. Match standalone and generated entries to original journals using explicit or verifiable source linkage, parties, dimensions and amounts. Move unique note, receipt, direction/payment semantics into admissible journal or voucher fields. Never generate a second posting for a matched entry. Do not reconstruct ambiguous historical voids or missing journals before finance approves the rules and reconciliation. Replace the entry table with a party-activity projection. |
| `inventory_items`, `stock_ledger` | Map to inventory masters and stock movements. Reconstruct opening movement only from evidence. Reconcile quantity, dates, sources and recorded costs, including returns/voids. Detect precision loss before numeric conversion. Existing running quantity is reconciliation input. |
| `audit_logs` | Preserve legacy actor/source/hash chain evidence in restricted archival exports. Import validated history as provenance-marked audit events where sustainable. New events are server-attributed and immutable. |
| Local `sync_outbox`, `sync_state` | Convert to operation outbox and workspace sequence checkpoints. Accepted cloud facts get a new-epoch baseline. Timestamp cursors have no direct translation. Rebuild unaccepted operations with expected revisions under the target contract. Do not auto-replay a raw legacy posting bundle without proving complete and unambiguous intent. |
| Cloud sync RPCs and policies | Replace legacy mutation interfaces and assigned broad grants with controlled, scoped command/pull access after compatibility and permission verification. The private commit feed supports the new protocol only. |

### Structures scheduled for retirement

- Duplicate personal/profile/company identity records and their revision or owner copies. Remove embedded workspace lists, global workspace preference keys, legacy profile roles and placeholder IDs from active models. Retain only migration evidence and time-limited compatibility mappings.
- Expense category overlays in Ledger accounts, old Expense voucher/posting copies and duplicate legacy budget or recurring tables. Retire after verifying all read/write paths and reconciling Ledger-specific legacy rows. Preserve historical source evidence under the approved retention policy.
- Independently mutable `ledger_entries`, synchronized current/running balance fields and duplicate subtotal projections where they are derivable and carry no document snapshot semantics. Keep document and statutory snapshots that must stay fixed.
- Unused device and attachment structures after checking real dependencies and attachment decisions. Legacy outbox cursor formats and superseded RPCs after old-client retirement. Generated test fixture history stays available for upgrade tests.

## 3. Execution phases for a later implementation

| Phase | Change and exit condition |
| --- | --- |
| A. Rehearse | Build additive target schema in a disposable environment after catalog reconciliation. Verify clean install, roles/grants, integrity, policy outcomes and restored backup behavior. Account for existing table names via an explicit staging schema or versioned API boundary and define rename timing. |
| B. Backfill | Take a consistent source snapshot with a reliable cutover boundary. Backfill in dependency order from identities/workspaces to subtype, roster, masters, documents, postings and stock. Repeat idempotently from the mapping manifest. Validate scoped constraints, row counts and financial totals. Report unresolved exceptions by workspace. |
| C. Catch up | Permit legacy writes only through the agreed pre-cutover interface. For the final delta, fence writes during an authorized maintenance window unless a verified ordered change-capture stream is implemented. Reconcile final ledgers and storage, capture an initial workspace snapshot and establish new protocol heads. No uncontrolled dual writing. |
| D. Activate | Switch one workspace only when all gates pass. Fence old writes for activated workspaces at the server, require compatible clients, and bootstrap authorized devices. Validate target reads, accepted operations, new feed ordering and revenue/tax/stock reports. Preserve pre-cutover evidence while observing. |
| E. Retire | End compatibility when device adoption and queued-work recovery meet agreed thresholds. Archive permitted source data and remove legacy objects only after a separate approved, rehearsed cleanup. Verify old mutations are inaccessible under final grants. |

Before target writes are accepted, rollback can return the workspace to the legacy path under a write fence. After target writes begin, disable new mutations and restore service only with proven reverse reconciliation of all accepted operations or a forward fix. Pointing a client at a stale legacy database would lose accepted changes. A rollback exercise must demonstrate account/workspace visibility, storage references, numbers and posting totals after recovery.

## 4. Planned Drift changes

- Create UID-scoped schema mirrors for users, workspace/types, membership metadata if needed, and normalized finance rows. Use canonical UUID TEXT, signed 64-bit-compatible INTEGER for money, exact scaled INTEGER for approved fractional quantity/percentage precision with explicit range checks, canonical UTC timestamps and unambiguous local-date fields. Preserve FKs, uniqueness and subtype pairing via database constraints where SQLite supports them and atomic repository boundaries otherwise. Enable FK validation and verify it before exposing migrated data.
- Replace row upsert queue with local `pending_operations`: operation UUID PK, UID and workspace, command kind/version, immutable payload and dependency/base revisions, state, retry count, retry time, last error and creation time. Keep immutable request bytes once eligible to send. Pending effects can remain as a rebuildable overlay over confirmed rows. Conflict decisions and quarantined records stay in UID-scoped local state.
- Replace timestamp cursors with `workspace_sync_state`: workspace PK, feed epoch/protocol, last sequence, snapshot status and last confirmed time. Store device selection by UID with workspace validation. Apply accepted batches and checkpoints in a single transaction. Reserve resnapshot space and test interrupted application.
- Keep old file untouched until the migrated file opens, validates and exposes the same approved financial totals. Test interruptions and legacy guest ownership recovery with no reuse across identities. For older unsent data, explicitly retain failed or unresolved operations in an exportable recovery queue.
- Regenerate current Drift artifacts and add versioned fixtures for fresh schema, all supported upgrade chains, typed scope constraints and upgrade resume. Rewire provider/repository contracts after review. The exact Application, sync and model paths are listed in the [audit source impact](database_audit.md#8-target-disposition-and-exact-source-impact).

## 5. Acceptance tests

| Gate | Required checks |
| --- | --- |
| Identity and lifecycle | OTP and email flows provision one self row without a workspace. An owner can create multiple UUID workspaces offline. Each parent commits with one matching subtype, and attempts to insert missing or wrong types, reparent data, or update owner outside approved paths fail. Archive, restore and deleted markers produce the specified UI/access state. |
| RLS and authorizations | With real Postgres roles, anonymous and unrelated users see no rows, delegated roles provide zero launch access, raw writes fail, and owner scope is derived from persisted targets. Verify row, RPC, view and Storage permissions across two accounts and two workspaces of one account. Ordinary writes cannot modify posted rows, immutable audit or actor metadata. |
| FK and CHECK rules | Reject cross-workspace and cross-type references including wallet transfers, category/account trees, voucher lines, journal dimensions, recurring templates and inventory sources. Verify delete restrictions, category/account cycle checks, per-workspace uniqueness, NULL overall budget uniqueness and same-workspace ownership of Storage keys. |
| Expense financial correctness | Verify opening amounts, both sides of transfers, edit/delete/recovery, archive and current wallet projections. Budget filters and period cases match approved rules. Verify recurring simultaneous generation, offline duplicate occurrence, tombstoned occurrence, month-end and relevant time-zone cases. |
| Ledger financial correctness | Verify sales, purchase, receipts, payments, contra, standalone credit/payment and opening operations. Compare AR/AP, trial balance, P&L, tax and stock reports. Fail partial or unbalanced posting. Verify unique document numbers, document conversion, accurate tax snapshots, and inverse journal and stock movements on reversal. Assert exactly one party-control effect per intended movement. |
| Sync protocol | Retry after lost response, restart between send and acknowledgment, and reject an operation ID reused with a different payload. Simultaneous stale edits cannot overwrite accepted changes. Competing workspaces cannot access each other's sequences or receipts. Apply whole batches with a transactional checkpoint during crash and restart. Verify consistent snapshots under concurrent writes, expiration, retention and tombstones. |
| Data migration | Reconcile counts and signed minor-unit totals per workspace/currency/account/party/wallet/period, and stock per item. Compare posted versus unposted and historical versus corrected values. Every row is mapped or in an explicitly accepted exception set. Validate deduplication, unchanged legacy sources during rehearsal, checkpoint reset, old-client write fence and recoverable pending work. |
| Operational rollout | Demonstrate restored backups and pre/post-activation recovery, observe rejection/conflict/error rates and replication lag, confirm retention and known capacity for receipts, and review plans for scope queries using realistic sizes. |
